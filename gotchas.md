# Gotchas

- A requested animation showcase must contain executable, visible state transitions. Static terminal sketches do not count. Before opening Lavish, verify a finite timeline changes DOM state, settles, and exposes replay plus reduced-motion controls.
- When a Lavish poll exits, inspect the logs of that exact completed poll process before starting another poll. The exit notice does not include the feedback payload.
- Signal mockups must expose concrete operator value. Abstract lifecycle states and unexplained acronyms are not useful evidence.
- Terminal emphasis must not shift glyph columns or open gaps. Use non-layout color, brightness, text-shadow, or glyph changes.
- A high-ceiling animation prototype cannot stop at text replacement and color pulses. Demonstrate at least one procedural subcell renderer, explicit topology renderer, or multiscale temporal renderer, and make structurally different motion dialects directly comparable.
- New animation ideas must pass an OMP ownership firewall: attach only to an existing plugin-owned renderer/chrome slot. If OMP already owns the user-facing fact or action, reject the idea instead of adding a duplicate row, badge, prompt, or parallel state.
- A provenance tree needs one continuous fixed-indent root→trunk→edge structure. Separate ROOT and EDGE rows read as a disconnected list even when the glyphs are individually correct.
- Skill-chain arrows mean observed same-actor invocation order unless explicit dependency metadata exists. Show a skill as current only during an authoritative invocation; after completion, label it latest/recent instead of active.
- Agent activity gloss must be finite and event-driven. Its speed may classify exact per-agent update cadence with hysteresis, but never productivity or percent complete; idle does not shimmer, stall settles once to static gold, and explicit block settles once to static vermillion.
- Per-section replay must reuse the canonical showcase timeline while filtering mutations to the selected `data-demo`. Before a solo replay, cancel the shared frame and clear every transient animation class so sibling facts and pixels freeze exactly where they are.
- Provenance topology is one visual object: root, trunk, and child edges use one uniform semantic color. Distinguish pending/active/complete substeps with glyphs and text, not per-level coloring that makes build/test look detached.
- Experimental visual additions must start from a current plugin signal and a user-visible problem. Theme-first spectacle is out of scope even when it can be made finite and technically safe.
- Never `respawn-pane -k` to reload a visual sandbox while that pane is running user work. Inspect for activity first; verify edits in a separate fake-HOME pane, or get explicit permission before replacing the user's process.
- When Rohit rejects a family of visual metaphors and says to keep the default progress bar, terminate that design branch. Preserve the bar byte-for-byte and redirect ideation to distinct operator problems; renamed gauge variants are not new ideas.
- In hashline patches, hunk headers never start with `+`. A `+PUT ...` line becomes literal file content; inspect warning output and remove it immediately.
- When adding a field to an interface with a hashline patch, insert before its closing brace. Anchoring after the brace creates a top-level property and breaks parsing.
- For `/lavish`, do not inherit Rohit's personal design system unless he explicitly asks for it. Use the generic Lavish Tailwind/DaisyUI fallback for standalone showcase artifacts.
- If a Lavish review is visibly broken, end its session and delete only the artifacts created for that failed review after reference verification. Rebuild a self-contained static artifact; avoid CDN/runtime dependencies that can fail inside the Lavish frame.
- Before deleting a Lavish artifact, end its session and stop the Lavish server; otherwise stale browser/session state can reopen the removed path and surface an ENOENT instead of the replacement review.
- A Lavish showcase for `@oh-my-pi/animations` must lead with the actual Animations Box surface, real row order, real signal names, and project file paths. A generic dashboard with invented telemetry is not a plugin showcase, even if its motion is executable.
- A browser prototype for a terminal feature must not imply CSS glow, continuous vector motion, hover, card graphs, or mouse controls will ship. Constrain the showcased product surface to fixed-width terminal cells, and prove the design at 45, 69, and 120 columns; keep browser-only review controls outside that surface.
- Before sharing or re-sharing a Lavish URL, reopen the artifact with `lavish-axi`, fetch the exact session URL, and verify it returns the artifact. A previously valid localhost URL is not evidence that the idle review server is still running.
- Before `tmux respawn-pane -k`, validate the full launch command and entrypoint in a disposable process. A typo destroys the pane before the replacement process can report its error.
- Never start the sandbox omp with `--no-session` when proving roster-driven signals (`N writers`, `write-clash`). Without a session file the host leases subagents into `/tmp/omp-task-*` outside the roster scope, so every subagent tool call is dropped while the Bonsai still names the agents; the absence looks like a plugin bug but is a launch flag.
- Subagents dispatched to Treehouse worktrees have written into the primary checkout even when told not to; snapshot primary with `scripts/worktree-tripwire.sh snapshot` before dispatch and `verify` after, and treat a worker's "primary untouched" claim as unverified until verify prints clean.
